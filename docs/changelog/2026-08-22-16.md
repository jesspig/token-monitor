## 环境坑修复：better-sqlite3 ABI 双运行时冲突

- 现象：`pnpm dev` 启动即崩，报 `NODE_MODULE_VERSION 137 vs 130`——better-sqlite3 安装时按系统 Node v24（ABI 137）编译，Electron 33.4.11 需要 ABI 130。
- 根因：better-sqlite3 原生二进制的编译目标 ABI 与 Electron 运行时不匹配。
- 修复动作：`pnpm dlx @electron/rebuild -f -w better-sqlite3 -v 33.4.11` 将二进制重编为 Electron ABI，已验证 Electron 运行时下建表/读写正常；副作用是系统 Node 下 vitest 无法再加载该二进制。electron-builder 打包流程不受影响（其自带 install-app-deps 重编逻辑）。
- 测试命令变更：改用 Electron 内置 Node（v20.18.3）跑测试，全量 21 文件 / 222 用例全绿：

  ```
  $env:ELECTRON_RUN_AS_NODE='1'; & "node_modules\electron\dist\electron.exe" node_modules/vitest/vitest.mjs run
  ```

- 禁止事项：不要再以 `pnpm exec vitest run` 直接跑主进程相关测试（ABI 报错）；也不要再对 better-sqlite3 执行面向系统 Node 的 rebuild（会反过来弄坏 dev）。
