# 2026-08-28 多维与性能迭代（feature/multidim-ui-perf）

> 按小时合并记录。本条目对应 feature/multidim-ui-perf 分支的 16 项任务；验证闭环为 typecheck 双段 + 经 Electron 内置 Node 跑 vitest 全量。

## 目标
- **UI/UX**：引入更多图表并将数据表格按维度拆分，使用户能便捷地从多维度了解使用情况。
- **性能**：异步、多线程、增量更新等手段减轻计算压力、提升响应速度。

## 任务与实现

### 渲染层（A1–A4, B1–B3, D1–D2, B2）
- **A1** 新增 `components/DimensionChart.tsx`：ComposedChart 通用组件，支持多序列（key/name/color/axis/chartType: area/line/bar）、左/右双 Y 轴、暗色渐变，`React.memo` 导出。
- **A2** 新增 `components/ShareChart.tsx`：占比图（pie/bar，暗色主题，空态复用 `EmptyState`），默认调色板循环，与 DimensionChart 协调。
- **A3** `DashboardPage` 改用 DimensionChart：`trend` 含 requests/inputTokens/outputTokens/cacheReadTokens/cacheCreationTokens/costUsd 六序列（costUsd 字符串转 number，右轴 line），复用原 today/24h 小时桶分支。
- **A4** `TrendsPage` 改用 DimensionChart：双图（请求 line；Token 四 area + 成本 line 右轴）复用组件，移除重复内联样式与 recharts 重复导入。
- **B1** 新增 `context/FilterContext.tsx`：共享筛选 `{range, appTypes, models, project, status}`，`useFilter()` 抛错守卫，`FilterProvider` 在 App 根挂载。
- **B3** 详情抽屉一键过滤：`components/NavContext.tsx` 新增（`PageKey` 唯一来源，`NavProvider` 持有 page/setPage/navigate，`useNav()`），`App.tsx` 拆为 `App`+`AppShell` 并用 `NavProvider` 包裹；`RequestLogsPage` 新增 `viewInTrends()` 设置 appTypes/models 并 `navigate('trends')`。
- **跨页筛选消费**：`TrendsPage` 合并 `filter.filter.appTypes/models` 到查询；`RequestLogsPage` 用 `useEffect` 把 `sharedFilter` 的 appTypes/models/project 同步进本地 state，使下钻真正过滤（组件重挂载时上下文持久）。
- **D1** 新增 `hooks/useDimensionStats.ts`（`DimensionKey= model|app|project|session|status`，`useQuery` 映射到对应 `api.getStatsBy*`）与 `components/DimensionTable.tsx`（五维切换+列排序▲▼+合计行+费用占比 ShareChart，`rangeToFilters` 生成过滤，`Number(costUsd)` 作 ShareChart 数值）。
- **D2** 重写 `StatsPage` 为外壳（`PageHeader`+`RangeSelector`+`<DimensionTable range={range} onRowClick>`），删除旧 model/app tab 与手写双表。
- **B2** 行点击下钻：`DimensionTable` 加可选 `onRowClick?: (row,dimension)=>void`（`cursor-pointer`）；`StatsPage` 修正 DimensionTable 为默认导入，`handleDrill` 按维度回填 `setModels/setAppTypes/setProject` 并 `navigate('logs')`（row 用 `as {model:string}` 等断言窄化联合类型）。
- **修复**：`FilterContext` 初始 import 由 subagent 自动修正；`DimensionTable` 移除未用 `useQuery` 导入；`StatsPage` handleDrill 按维度断言取字段消除联合类型报错。

### 主进程（C1–C3, E1–E2）
- **C1** 聚合查询通用化：`usageQuery.ts` 抽 `queryGroupBy<T>(db,filters,spec)` + `PathSpec`/`GroupBySpec`/`MODEL_AVG_LATENCY_*`/`buildMetricsExpr`，5 聚合函数（summary/daily/model/app/hourly）全部改为调用通用函数，`buildWhere`/`canUseRollups`/`prepareCached` 保留，SQL 注入仅内部常量白名单；行为不变（cost 微美元整数累加后 `fromMicroUsd`，model 平均耗时 rollup/m明细一致）。
- **C2** 新增 `shared/query.ts: ProjectStats/SessionStats/StatusStats` 与 `UsageQueryService.getStatsByProject/Session/Status` + `usageQuery.ts: queryProjectRows/SessionRows/StatusRows`（detail-only，不传 rollup，`detailWhereExcludingNull` 过滤项目/会话/状态非空，`orderBy: request_count DESC`，mapped 后 `slice(0,200)`）。
- **C3** 贯通 `RendererApi`（`shared/ipc.ts` 20 方法）→ `IPC_CHANNELS statsByProject/Session/Status` + handler（`register.ts`）→ `worker/queryClient.ts facade`（三方法）→ `preload/index.ts`（三方法）→ `api.ts`/`mock.ts`（三方法，mock 基于 filterRecords 聚合）；`query-worker.ts` 动态派发无需分支。
- **E1** `worker/queryClient.ts` 池化：`WORKER_POOL_SIZE=2`，`HEAVY_METHODS`（getStatsByProject/Session/Status + getRequestLogs/getUsageSummary）→ pool[0]，其余轻查询 → pool[1]；统一 `inflight` 跨池去重与 `pending`/`nextId`，`error` 仅 reject 归属 worker 的 pending，`terminate()` 终止全池；`:memory:` 与缺 fallbackDb 回退路径保留。
- **E2** 采集层并发：`collector.syncAll` 改有界并发池 `SYNC_CONCURRENCY=4`（分批 `Promise.all`，文件级仍串行保游标/去重事务，addedRecords>0 才 emit），`dsh.listFiles` 目录列举改为 `fs.promises.readdir/stat` 异步（`safeReaddirAsync`/`toEntryAsync`，`collectSubtree` 变 async），探测链路保留同步；`dsh.test.ts` 收集范围用例改为 async+await。
- **修复**：`App.tsx` 标签不平衡（h-screen div 缺闭合）由 subagent 补 `</div>`；`queryClient.ts` 缺三方法 `QueryClientService` 报错在 C3 解决；`usageQuery.ts` 两处 `filters.status !== ''` 类型报错（`RequestStatus` 不含空串）删至 `filters.status != null`；`preload/index.ts` 缺三方法在 C3 后由 fix 补；`StatsPage` 命名导入改为默认导入。
- **E3（已回退）**：曾尝试给 rollups 物化表加 `project`/`status` 列并改 PK 为 (date,app,model,project,status)，但导致日/小时桶按状态拆桶、历史回填为 `''` 使 project/status 过滤查询漏算历史数据的风险已识别。经代码审查决定整体回退 E3（`db.ts` v11 移除、`storage.ts` bucket/upsert 恢复为 (date,app,model)、测试 `user_version` 断言恢复为 10），rollups 保持 (date,app_type,model) 主键；但历史回填为 '' 的漏算问题源头已消除，C2 维度查询保持 detail 路径（正确性优先）。分支最终 `MIGRATIONS` 最高版本为 10，rollups 无 project/status 列。
