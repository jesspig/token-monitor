## 变更一：计费语义修复（input_semantics 接入费用计算，P0 正确性）

- 经上游源码核实：codex / gemini / grok 三源的 `input_tokens` 为**含缓存 token 的总量**（codex 含 `cached_input_tokens`、gemini `promptTokenCount` 含 `cachedContentTokenCount`、grok `prompt_tokens` 含 `cached_prompt_tokens`，三者均无独立 write 桶），旧公式全额乘 input 价造成缓存部分重复计费、费用系统性高估；claude 与 opencode 的 input 已是纯新输入。
- `pricing.calcCost` 新增 fresh input 口径：`inputSemantics === 1` 时先 `max(0, input − cacheRead − cacheCreation)` 再乘 input 价；0/2 不扣。三态 SSOT 定义修订为「0=未知 / 1=含缓存总量需扣减 / 2=纯新输入」。
- **schema v4 迁移**：修正 opencode 存量行 semantics 1→2（opencode 上游 getUsage 已自行扣减缓存，原标注错误）；codex/gemini/grok 的历史费用重算由新增 `pricing.recalcCachedInputCosts(db, pricing)` 在宿主启动时以活定价完成（迁移函数为同步纯 SQL 拿不到定价），delta 增量修正 rollups、重算一致零写入幂等。

## 变更二：fork/rewrite 语义去重接入（dedup_ledger 从预留转为生效）

- `UsageRecord.source` 新增可选 `requestId`；五插件全部产出稳定语义 ID——claude=message.id、codex=`threadId:行timestamp:in-cached-out` 组合键（token_count 无 per-event id）、opencode=db 行主键 id 或旧版 JSON data.id、gemini=消息 UUID、grok=`sid:loop_index`。
- `storage.recordUsage` 入库事务内按 `(data_source, request_id)` 查 `dedup_ledger`：命中即跳过（不入明细、不计 rollup、不计 addedRecords、不触发 usage-updated）；插入成功回填账本（semantic_id = sha256 指纹前 16 位，仅存证）。无 requestId 记录退回既有 `file_path:line` 主键去重，行为不变。
- 新增 `services/dedup.ts`（semanticFingerprint）；±10 分钟时间窗指纹判重未实现（五源均有稳定 ID，YAGNI）。

## 变更三：采集与数据完整性

- **opencode WAL mtime 感知**：db 源条目 mtime 取主库与 `-wal` 较大值，消除 WAL 模式下 watcher 漏检（实时性不再退化到 5 分钟兜底扫描）。
- **保留清理前预回填**：调度触发的过期明细清理（runRetentionSweep）先尽力执行零成本回填再删除，缺价行不再因到期被删而永久丢失回补机会；回填失败仅记日志不阻塞清理。手动 `cleanupRetention()` 同步签名不变。

## 变更四：定价匹配增强

- normalizeModelId 追加第 8 步：剥离 reasoning effort 后缀 `-low/-high/-xhigh`（单次、$ 锚定）。
- matchPrice 扩为**五级兜底链**：①精确 → ②点转横线变体精确 → ③短 ID 前缀（最长 key）→ ④点转横线变体短 ID → ⑤家族兜底（key 以 model 为前缀且边界后继，取最短 key，model 长度 ≥3）。关键排序约束：点号精确变体必须先于一切前缀模糊，否则 `claude-opus-4.5` 会被短 ID `claude-opus-4` 截胡错配上一代价格（差 3 倍），已有防回归用例。
